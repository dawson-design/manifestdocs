**Decision.** Nodes get `fd-` plus 6 hex characters and decision records get `dc-` plus 7, from the operating system's random source. The tool generates a new ID when one matches an existing ID, and `check` reports duplicates. IDs of 4 or more characters are accepted when reading.

**Why.** People and agents create IDs on parallel branches, so IDs must be random. With 4 hex characters, two branches picking the same ID is 7% likely in a 500-node tree and 98% likely across 5,000 records. Six and seven characters bring those to 0.03% and 0.09%, and `check` on the default branch catches the clashes that remain.

**Rejected.** Sequential numbers, which clash on parallel branches as adr-tools' ADR numbers do. Content hashes, which change when titles change. Full-length ULIDs, which nobody would type. Enforcing "never reused", which no file can do.
